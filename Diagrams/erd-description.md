# Entity Relationship Diagram (ERD) Description

The Entity Relationship Diagram (ERD) defines the logical architecture of the Integrated Library Management System’s centralized database, establishing a structured relational schema that maps the interconnections across expanded primary operational domains: student management, multi-modal authentication, locker depository transactions, administrative reporting, institutional surveys, dynamic system configuration, AI-assisted administration, and immutable audit logging.

**Core Entities and Institutional Focus Areas**
The architectural center of the ERD is the student information repository (`tbl_student_info`), which serves as the primary relational hub for student access logs (`tbl_student_logs`, `tbl_access_attempts`), depository locker transactions (`tbl_rfid_info`, `tbl_rfidhistory`), and administrative accounts (`users`). These structured relationships ensure that every institutional event—whether an entry verification, attendance recording, locker borrow/return cycle, or unrecognized authentication attempt—remains fully traceable to a validated student profile and an authorized administrator account.

**Multi-Modal Access and Locker Depository Tracking**
By architecting `tbl_access_attempts` and `tbl_rfidhistory` with explicit relational dependencies to `tbl_student_info` and `users`, the ERD facilitates a robust multi-modal authentication framework that synchronizes physical locker assignments in real time. This relational linkage guarantees that RFID-based depository operations immediately update resource availability (`tbl_rfid_info.IS_AVAILABLE`) and generate auditable transaction records that link the borrowing student directly to the specific library personnel who facilitated the request.

**Administrative, AI Assistance, and Institutional Survey Modules**
The ERD further integrates comprehensive administrative management through the implementation of `tbl_lost_id_reports`, `email_messages`, `surveys`, `survey_questions`, and `survey_responses`, connecting students to formal communications and evaluative feedback campaigns. Administrative scheduling is structured through `calendar_notes`, while internal decision support is formalized via the `chats` and `chat_messages` tables, capturing relational conversational histories for the integrated AI Assistant. System-level parameters, encompassing facial recognition sensitivity thresholds (`tbl_sensitivity_thresholds`) and general application settings (`tbl_settings`), are similarly archived within this consistent relational structure to ensure that business rules remain dynamic and centrally managed.

**Role in Data Integrity and Architectural Design**
As a foundational technical artifact of the capstone project, the ERD enforces referential integrity and data coherence across all integrated modules. The recent architectural expansion significantly enhances institutional accountability through the `audit_trails` table, which utilizes polymorphic relationships and database-level triggers to enforce strict immutability—precluding any unauthorized deletions or modifications to system logs. The ERD provides a definitive visual blueprint for development stakeholders, ensuring the accurate implementation of core features while establishing a highly secure, scalable structural foundation for future system maintenance.
